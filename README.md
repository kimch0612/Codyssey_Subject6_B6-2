# 내가 고친 코드 설명을 AI가 대신 써주는 도우미

Git 변경 사항(`git status`, `git diff`)을 수집해 Google Gemini API로 커밋 메시지와 Pull Request 초안을 자동 생성하는 Python CLI 도구입니다.

## 특징

- 표준 라이브러리만 사용 — 별도 패키지 설치 없이 바로 실행 가능
- 커밋 메시지 / PR 제목·본문(Why / What / How to Test) 자동 생성
- 생성 결과의 길이·형식을 코드로 검증하고 자동으로 다듬음
- `-safe-mode`로 diff에 포함된 API Key/이메일 등 민감정보 마스킹

## 설계

세 가지 책임을 의도적으로 분리했습니다.

- **Git 데이터 수집** (`get_git_status`, `get_git_diff`, `get_current_branch`): `subprocess`로 git 명령을 실행해 문자열을 반환하는 역할만 합니다. AI나 네트워크를 전혀 모릅니다.
- **AI 호출** (`call_gemini`): 프롬프트와 파라미터를 받아 Gemini API를 호출하고 텍스트를 반환하는 역할만 합니다. git이나 커밋/PR 형식을 전혀 모릅니다.
- **오케스트레이션 + 후처리** (`run_commit`, `run_pr`): 위 둘을 조합하고, 결과를 검증·다듬어 출력까지 담당합니다.

이렇게 나눈 이유는 각 부분을 독립적으로 테스트할 수 있게 하기 위함입니다. `call_gemini`는 git 저장소 없이도 임의의 프롬프트로 단독 호출해 테스트할 수 있고, `get_git_diff`는 AI 호출 없이 git 동작만 검증할 수 있습니다. 개발 과정에서도 이 구조 덕분에 git 수집 → AI 연동 → 프롬프트 설계 → 출력 검증 순서로 각 단계를 하나씩 완성·테스트한 뒤 다음 단계로 넘어갈 수 있었습니다.

## 설치 및 실행 방법

Python 3.10 이상이면 됩니다. `requests`, `python-dotenv` 같은 외부 패키지가 전혀 필요 없고 표준 라이브러리(`urllib`, `argparse`, `re` 등)만 사용합니다.

```bash
git clone https://github.com/kimch0612/Codyssey_Subject6_B6-2.git
```

이 도구는 **Git이 초기화된 프로젝트의 루트 디렉토리에서** 실행해야 합니다. 자기 자신의 저장소뿐 아니라, `main.py`의 경로만 가리키면 다른 어떤 git 프로젝트 안에서도 그대로 쓸 수 있습니다 (복사할 필요 없음).

```bash
cd /path/to/your-git-project
python3 /path/to/this-repo/main.py commit
```

## 환경변수(API Key) 설정 방법

1. [Google AI Studio](https://ai.google.dev/gemini-api/docs/quickstart)에서 Gemini API Key를 발급받습니다 (무료 티어로 사용 가능).
2. 발급받은 키를 환경변수 `AI_API_KEY`로 등록합니다.

```bash
export AI_API_KEY="발급받은_키"
```

API Key는 코드나 저장소에 직접 저장하지 않으며, 항상 이 환경변수를 통해서만 전달됩니다.

## 사용법

```bash
# 변경 사항을 요약한 커밋 메시지 생성
python3 main.py commit

# PR 제목/본문(Why / What / How to Test) 초안 생성
python3 main.py pr
```

### 옵션

| 옵션 | 설명 | 기본값 |
|---|---|---|
| `-model` | 사용할 Gemini 모델 | `gemini-3.1-flash-lite` |
| `-temperature` | 응답의 창의성/무작위성 (0~2, 낮을수록 일관적) | `0.3` |
| `-max-tokens` | 응답 최대 토큰 수 | `1024` |
| `-safe-mode` | diff에서 API Key/이메일 형태 패턴을 마스킹 후 전송 | 꺼짐 |

```bash
python3 main.py commit -temperature 0 -max-tokens 500
python3 main.py pr -safe-mode
```

`commit`/`pr` 명령은 각각 실행당 AI API를 1회만 호출합니다.

정상 종료 시 exit code `0`, API Key 누락이나 API 호출 실패 시 `1`을 반환합니다(변경 사항이 없어 그냥 종료한 경우는 실패가 아니므로 `0`). 셸 스크립트나 CI에서 `$?`로 성공 여부를 판단할 수 있습니다.

## 파라미터가 결과에 미치는 영향

### temperature

같은 프롬프트("오늘 날씨에 대해 짧고 창의적인 한 문장을 지어줘")를 온도만 바꿔 3번씩 반복 호출한 실제 결과입니다.

**temperature=0.0** (3회 반복 — 매번 동일)
```
오늘의 날씨를 한 문장으로 표현해 드릴게요. (현재 계신 지역의 날씨를 알려주시면 더 정확하게 지어드릴 수 있습니다!)
오늘의 날씨를 한 문장으로 표현해 드릴게요. (현재 계신 지역의 날씨를 알려주시면 더 정확하게 지어드릴 수 있습니다!)
오늘의 날씨를 한 문장으로 표현해 드릴게요. (현재 계신 지역의 날씨를 알려주시면 더 정확하게 지어드릴 수 있습니다!)
```

**temperature=1.8** (3회 반복 — 매번 다름)
```
오늘 날씨를 설명할 한 문장입니다. (오늘 계신 지역의 날씨에 맞춰 골라보세요!)
*   **맑고 화창할 때
---
오늘의 하늘은 마치 구름이 붓을 들고 마음껏 그려낸 투명한 수채화 같습니다.
---
오늘의 날씨를 생각하며, 원하시는 분위기에 맞춰 선택해 보세요!
```

0에 가까울수록 매번 같은 응답(결정적), 높을수록 매번 다른 응답(다양하지만 예측 불가)이 나옵니다. 이 도구는 커밋/PR 메시지가 실행마다 크게 달라지면 안 되므로 기본값을 `0.3`으로 낮게 잡았습니다. 실험해보고 싶다면 짧고 저렴한 명령(`-max-tokens`를 낮춰서)으로 값을 바꿔가며 같은 diff에 여러 번 실행해 비교해보세요.

### max_tokens

같은 프롬프트("파이썬이 왜 인기 있는 프로그래밍 언어인지 3문장으로 설명해줘")를 max_tokens만 바꿔 호출한 실제 결과입니다.

**max_tokens=15** (`finishReason: MAX_TOKENS`)
```
파이썬은 문법이 간결하고 직
```

**max_tokens=300** (`finishReason: STOP`)
```
파이썬은 문법이 사람의 언어와 유사하여 배우기 쉽고 코드가 간결해 생산성이 매우 높습니다. 또한, 방대한 라이브러리와 프레임워크를 지원하여 데이터 분석, 인공지능, 웹 개발 등 다양한 분야에서 즉시 활용할 수 있습니다. 이러한 범용성과 강력한 커뮤니티의 지원 덕분에 초보자부터 전문가까지 폭넓게 사랑받는 언어가 되었습니다.
```

`max_tokens`는 응답 길이의 상한선이지 목표치가 아닙니다 — 넉넉하게 주면 모델이 알아서 필요한 만큼만 쓰고 스스로 멈춥니다(`STOP`). 너무 낮으면 문장이 완성되기 전에 강제로 잘립니다(`MAX_TOKENS`). PR 본문은 Why/What/How to Test 세 섹션을 다 담아야 하므로 기본값을 `1024`로 넉넉하게 잡았고, 한글은 영어보다 같은 분량에 더 많은 토큰을 쓰는 경향이 있다는 점도 감안했습니다.

## 형식 위반 시: 재생성 대신 후처리를 선택한 이유

생성된 텍스트가 길이/형식 규칙(제목 길이, PR 섹션 구조)을 어겼을 때 두 가지 선택지가 있습니다.

| 기준 | 재생성(AI에 다시 요청) | 후처리(코드로 직접 수정 — 이 도구가 선택) |
|---|---|---|
| API 호출 횟수 | 실패할 때마다 추가 호출 필요 → `commit`/`pr`당 1회 제한과 충돌 가능 | 항상 1회로 고정 |
| 결과 보장 | 다시 생성해도 또 틀릴 수 있음(보장 없음) | 코드로 직접 고치므로 규칙 준수가 보장됨 |
| 적합한 경우 | 설명이 부정확한 등 내용 자체의 품질이 문제일 때 | 길이·구조처럼 기계적으로 판정·수정 가능한 규칙일 때 |

제목 길이 초과, PR 섹션 누락, 섹션 내 불릿 누락은 전부 코드가 "맞다/틀리다"를 명확히 판정하고 고칠 수 있는 규칙이라 후처리(`truncate`, `fix_pr_sections`)로 충분하다고 판단했습니다.

**후처리의 한계**: 누락된 섹션에는 실제 내용 대신 `- (내용 누락, 직접 작성 필요)`라는 플레이스홀더가 채워집니다. 형식 요건은 충족시키지만 내용까지 채워주지는 않으므로, 실행 로그에 `[WARN]`이 찍혔다면 해당 부분은 반드시 직접 검토·수정해야 합니다.

## 민감정보 대응 (Safe Mode)

`-safe-mode` 옵션을 사용하면 AI에 보내기 전 diff에서 아래 패턴을 마스킹합니다.

- 이메일 주소 → `[EMAIL]`
- `API_KEY = "..."`, `SECRET_TOKEN: '...'`처럼 민감해 보이는 변수명에 대입된 값 → `[MASKED]`

```diff
- NOTIFY_API_KEY = "AIzaSyD4example1234567890FAKEKEYXX"
- ADMIN_EMAIL = "admin@example.com"
+ NOTIFY_API_KEY = [MASKED]
+ ADMIN_EMAIL = "[EMAIL]"
```

변수 이름은 그대로 남기고 값만 가려서, AI가 "무엇이 추가됐는지"는 계속 이해하면서도 실제 키/이메일 값은 전송하지 않습니다. 다만 정규식 기반 탐지라 완벽하지 않으므로, 민감한 코드를 다룰 땐 생성 결과를 실제로 적용하기 전에 항상 직접 검토하시기 바랍니다.

## 적용 전 검토 체크리스트

생성된 커밋/PR 문구를 실제로 적용하기 전에 아래를 확인하세요.

- [ ] 실행 로그에 `[WARN]`이 있었다면, 해당 부분(잘린 제목 / 채워진 플레이스홀더 불릿)을 직접 수정했는가
- [ ] 본문의 불릿이 실제로 있었던 변경 내용과 일치하는가 — AI가 diff에 없는 내용을 지어내지(hallucination) 않았는지
- [ ] `-safe-mode` 없이 실행했다면, diff에 민감정보가 없었는지 다시 한번 확인했는가
- [ ] 팀/프로젝트의 커밋 컨벤션(prefix, 스코프 표기 등)과 맞는가

## 주의사항

- Gemini API는 무료 티어에서도 모델별로 분당/일일 요청 수 제한이 있습니다. 반복 실행 시 `HTTP 429` 오류가 날 수 있습니다.
- API 호출 실패(네트워크 오류, HTTP 오류 등) 시 자동 재시도는 하지 않습니다. 오류 메시지를 확인하고 같은 명령을 다시 실행하면 됩니다 — 재시도를 자동화하면 "실행당 1~2회 호출" 제한을 넘길 수 있어 의도적으로 넣지 않았습니다.
- 이 도구는 커밋/PR **초안 텍스트를 생성**하는 것까지가 목표입니다. `git commit`, `git push`, GitHub PR 생성 등 실제 반영은 직접 수행해야 합니다.
- 생성된 커밋/PR 문구는 최종 정답이 아니라 초안입니다. 항상 검토 후 적용하세요.
